# Blog: system-not-logo — shared semantic brief

```yaml
page_goal: Explain why a usable brand identity needs production rules as well as a mark.
primary_audience: [boutique_brand, rebuild_legacy, ops_panel]
visitor_problem: The logo changed, but the website, panel, documents, and components still look unrelated.
main_message: A CSS design system turns identity decisions into repeatable rules for type, color, spacing, states, and components.
proof_points: [source-controlled-design, reusable-internal-systems]
required_information:
  - Difference between a mark and an interface system
  - Minimum useful token and component set
  - How public and internal surfaces share rules without becoming identical
  - A practical audit for an existing brand
desired_action: Audit the current interfaces or discuss a design-system engagement.
search_intent: Informational with light commercial follow-through.
tone_constraints: Expert and practical; no anti-logo provocation used as a substitute for the argument.
claims_not_allowed: [brand lift %, conversion lift %, universal design rules]
```
